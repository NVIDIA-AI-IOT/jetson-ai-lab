[Voice AI Workbench](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio), formerly **Multi-modal AI Studio (MMAS)**, helps developers give a robot a voice and a character. Compare independent ASR, LLM/VLM, and TTS services through standard APIs, tune the LLM's system prompt, and inspect recorded transcripts, latency, barge-in, audio playback, and device utilization. Optional vision input remains supported. The GitHub repository and existing session formats retain their original names; the recommended package and CLI name is now `voice-ai-workbench`.

For **Jetson AGX Thor**, start with NVIDIA open speech models and **Cosmos3-Edge**: Nemotron 3.5 ASR (Parakeet-family) → Cosmos3-Edge Reasoner → Magpie TTS. For **Jetson Orin Nano and AGX Orin**, use the smaller Speaches + Gemma 4 E2B quick start. Both paths use public model services through standard APIs, without installing the Riva SDK or requiring an NGC entitlement.

<Note title="Application and backend versions">
  [Voice AI Workbench 0.2.0](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/releases/tag/v0.2.0) is available on [PyPI](https://pypi.org/project/voice-ai-workbench/0.2.0/). The GitHub release provides artifacts, checksums, and limitations. The independently versioned Speaches backend remains pinned to 0.9.0-rc.3; the workbench release does not make that backend a GA release. Use the REST path for the Speaches quick start; the NVIDIA speech services have a separate native Realtime ASR path.
</Note>

## Install the application

- A Jetson Orin or Thor running a Jetson Linux release whose driver supports CUDA 13 containers
- Docker with the NVIDIA container runtime
- A Chromium-based browser on the Jetson or another computer on the same trusted network
- Enough free storage for the selected container images and model cache

Install the published application in an isolated Python 3.11+ environment. Clone the matching release only for the backend launcher scripts; the installed wheel supplies the Web UI and built-in presets.

```bash
python3 -m venv ~/voice-workbench-venv
source ~/voice-workbench-venv/bin/activate
python -m pip install voice-ai-workbench==0.2.0
voice-ai-workbench --version

git clone --branch v0.2.0 --depth 1 \
  https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio.git \
  ~/voice-workbench-backends
cd ~/voice-workbench-backends
```

The commands below run the backend scripts from `~/voice-workbench-backends`. The application is launched from outside that checkout so Python uses the installed wheel rather than importing source files from the current directory.

If creating the environment fails because `ensurepip` is missing, install your OS's matching venv package, such as `sudo apt install python3-venv`. Browser audio does not require the optional PyAudio package. Keep earlier `multi-modal-ai-studio` installations in a separate environment; see the [upgrade instructions](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/main/docs/development/releasing.md#upgrading-an-earlier-mmas-installation) before reusing one.

## Thor: NVIDIA open speech models + Cosmos3-Edge

This is the first configuration to try on **Jetson AGX Thor**. Keep the three services independent so each can be evaluated or replaced without rebuilding the application:

```text
browser microphone
  -> Nemotron 3.5 ASR, Parakeet-family (:8081)
  -> Cosmos3-Edge Reasoner, vLLM (:18087)
  -> Magpie multilingual v2607 (:8082)
  -> browser speaker
```

The ASR checkpoint's exact name is <code class="break-all">nvidia/nemotron-3.5-asr-streaming-0.6b</code>; its cache-aware encoder is from the Parakeet family. It is not the older Parakeet 1.1B Riva artifact. Cosmos3-Edge's **Reasoner** provides text and image understanding through Chat Completions; this tutorial does not run its video-generation or robot-action server.

“Open models” means publicly downloadable checkpoints with local inference here, not identical licenses for every component. Review each model's terms for your intended product.

### 1. Start NVIDIA ASR and TTS

From the matching backend checkout created above:

```bash
cd ~/voice-workbench-backends
./scripts/nvidia_open_models_speech.sh doctor
./scripts/nvidia_open_models_speech.sh build
./scripts/nvidia_open_models_speech.sh start
./scripts/nvidia_open_models_speech.sh verify
cd ~
```

The first build and checkpoint downloads can take time. This launcher manages **speech only**; it does not start an LLM. It exposes REST and WebSocket Realtime APIs at ports 8081 and 8082. See the [NVIDIA speech setup guide](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/v0.2.0/docs/setup_open_models_jetson.md) for the qualified images, model revisions, storage, and restart commands.

### 2. Serve the Cosmos3-Edge Reasoner

Use the **vLLM Reasoner** deployment, not the vLLM-Omni Generator / Action deployment, on the [Cosmos3-Edge model page](/models/cosmos3-edge/). The following single-session settings shorten the context and leave shared-GPU memory for ASR and TTS; port 18087 also avoids replacing an existing E2B server:

```bash
sudo docker run -it --rm --pull always \
  --runtime=nvidia --network host \
  -v $HOME/.cache/huggingface:/root/.cache/huggingface \
  --entrypoint "" \
  vllm/vllm-openai:cosmos3 \
  vllm serve nvidia/Cosmos3-Edge \
    --host 127.0.0.1 --port 18087 \
    --trust-remote-code --dtype bfloat16 \
    --max-model-len 4096 --max-num-seqs 1 \
    --gpu-memory-utilization 0.15 --enforce-eager \
    --limit-mm-per-prompt '{"image":1,"video":0}' \
    --mm-processor-kwargs '{"do_resize":true,"min_pixels":4096,"max_pixels":262144}'
```

Keep this terminal running. From another terminal, verify the model API:

```bash
curl --fail http://localhost:18087/v1/models
```

The model page is the reference for supported engines and hardware. These shared-service settings are a starting point for AGX Thor, not a claim that this vLLM configuration fits an 8 GB Orin Nano. Do not start multiple full-size LLM servers unnecessarily.

### 3. Connect the workbench

Activate the installed application environment, then run it from outside the backend checkout:

```bash
source ~/voice-workbench-venv/bin/activate
cd ~
voice-ai-workbench \
  --preset nvidia-open-models-realtime-speech-jetson \
  --llm-api-base http://localhost:18087/v1 \
  --llm-model nvidia/Cosmos3-Edge \
  --llm-max-tokens 128 \
  --port 8092
```

Open `https://<JETSON_IP>:8092` on a trusted network. Select the browser microphone and speaker for the first test. The NVIDIA preset retains the speech models and supplies <code class="break-all">chat_template_kwargs.enable_thinking=false</code> in **Extra Request Body**; Cosmos3-Edge otherwise enables thinking by default. In **LLM / VLM**, leave **Enable reasoning (chain-of-thought) through user prompt** off and use a short spoken-answer system prompt. That checkbox adds an application prompt; it is not a substitute for the server-side request setting. In **TTS**, turn **Start speaking before LLM finishes** off for the first baseline, then evaluate overlap separately.

Try “What is one plus one?”, followed by “Explain the history of robotics.” While the assistant is speaking, say “Stop, what is two plus two?” Confirm that the old audio stops, the new answer is audible, and the saved session reopens correctly.

For the file-based speech baseline, change only `--preset` to `nvidia-open-models-speech-jetson` and keep the same Cosmos endpoint and model overrides. This compares REST endpointing with native Realtime ASR without changing the LLM.

<Note title="What streams in this configuration">
  Nemotron Realtime ASR uses its cache-aware streaming model and can return partial transcripts while you speak. Magpie's Realtime adapter returns PCM delta events for completed text chunks; the current model path is phrase-level generation, not model-native incremental waveform synthesis. The workbench's early-TTS setting is a separate text-chunking choice.
</Note>

### 4. Add vision after voice works

Enable vision under **Configuration → LLM / VLM**, select a browser camera under **Devices**, and begin with one small frame per turn. Ask a question whose answer depends on what the camera sees, then change the scene and repeat. See the [vision setup guide](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/v0.2.0/docs/vlm_guide.md) for optional camera dependencies and frame settings.

This is a voice-and-vision assistant, not a robot control policy. Cosmos3's action-generation capabilities require a different serving path and embodiment-specific integration; the workbench does not turn a spoken answer into safe robot motion.

## Orin quick start: Speaches + Gemma 4 E2B

This smaller configuration is the starting point for Orin Nano and AGX Orin. It can also be used as a compact comparison on Thor.

The starter pipeline is entirely local:

```text
browser microphone
  -> Speaches Faster-Whisper (:18080)
  -> Gemma 4 E2B llama.cpp (:8080)
  -> Speaches Kokoro (:18080)
  -> browser speaker
```

Speaches exposes OpenAI-compatible speech APIs. Gemma is a separate OpenAI-compatible Chat Completions service, so you can replace the LLM without restarting speech.

<Warning title="Orin Nano memory headroom">
  On an 8 GB Orin Nano, stop unrelated GPU workloads before starting the pipeline. A 16 GB swap file is strongly recommended to absorb transient CPU-side allocations while the models load. Swap does not increase GPU memory; the default tiny ASR model, 2048-token Gemma context, and text-only `--no-mmproj` configuration keep the active pipeline small enough for this device.
</Warning>

### 1. Start and verify speech

```bash
cd ~/voice-workbench-backends
./scripts/speaches_speech.sh doctor
./scripts/speaches_speech.sh start
./scripts/speaches_speech.sh verify
```

The launcher pulls the pinned dual-architecture CUDA image and installs these starter models in a persistent Docker volume:

<div style="overflow-x: auto;">

| Stage | Model |
| --- | --- |
| ASR | `Systran/faster-whisper-tiny.en` |
| TTS | `speaches-ai/Kokoro-82M-v1.0-ONNX-fp16` |
| Default voice | `af_heart` |

</div>

`verify` synthesizes a short sample through the TTS API and transcribes it through the ASR API. Do not continue until it prints `Speech API smoke test passed`.

### 2. Start and verify Gemma 4

```bash
./scripts/gemma4_llm.sh doctor
./scripts/gemma4_llm.sh start
./scripts/gemma4_llm.sh verify
```

The launcher selects the Jetson Orin or Thor llama.cpp image automatically and serves `unsloth/gemma-4-E2B-it-GGUF:Q4_K_S`. It enables Gemma's MTP draft, disables hidden reasoning for lower time to first speech, limits context to 2048 tokens, and skips the multimodal projector because this starter configuration uses Gemma as a text LLM.

### 3. Start the workbench

```bash
cd ~
voice-ai-workbench --preset speaches-jetson --port 8092
```

Open the URL printed by the server, normally:

```text
https://<JETSON_IP>:8092
```

After verifying that the address belongs to your Jetson on a trusted network, accept its local development certificate, allow microphone access, select **Check servers**, and start a session. Try these short prompts:

```text
Hi, can you hear me?
What is one plus one?
Tell me one short safety rule for a home robot.
```

While the assistant is speaking, test interruption with:

```text
Stop. What is one plus one?
```

When you stop the session, select it in the left sidebar to review the transcript, audio waveforms, pipeline timeline, time-to-first-audio measurements, and Jetson system information.


### From a browser test to a robot's audio devices

Start with the **Browser / WebRTC** microphone and speaker selections in the **Devices** tab. They use the computer that opened the page, while model inference runs on Jetson. This is the simplest way to compare models, adjust the system prompt, and measure responsiveness without attaching audio hardware to the robot.

Once the conversation works, connect a USB microphone and speaker to Jetson and select the **Server USB** devices instead. Save a separate preset with those device choices so the robot uses its own audio hardware, not the laptop's. Recheck capture, playback, and barge-in: acoustic echo, device sample rates, and microphone levels differ between the two paths. A speakerphone with acoustic echo cancellation or a headset is useful during testing.

The CLI also offers experimental headless operation using a saved configuration. See the [device and headless setup instructions](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/main/INSTALL.md) before deploying without a browser; a successful browser test alone does not qualify the server-local device path.

### REST and Realtime speech paths

The default `speaches-jetson` preset uses REST transcription and speech APIs. The workbench detects speech boundaries locally and sends each completed utterance as a WAV request. Its Realtime ASR adapter instead sends microphone audio over a WebSocket and consumes the backend's speech-boundary and transcription events. Realtime ASR does not require Realtime TTS; the Speaches Realtime ASR preset keeps Kokoro on the REST speech API.

<Warning title="Speaches Realtime evaluation">
  Concurrent ASR, LLM, and TTS testing on Orin Nano exposed errors and delayed interruption with the pinned public Speaches 0.9.0-rc.3 image. Follow-up tests passed with a locally corrected backend, but that corrected image is not yet published. Updating Voice AI Workbench alone does not install those server fixes. Keep the REST preset for the recommended public quick start; the Realtime command below is an optional diagnostic path, not equivalent qualification of the public image.
</Warning>

To evaluate the Realtime ASR path against a suitable backend, stop the current workbench process with **Ctrl+C** in its terminal, then restart it with the alternate preset. Keep the model services running:

```bash
cd ~
voice-ai-workbench --preset speaches-realtime-asr-jetson --port 8092
```

Speaches emits Realtime session and speech-boundary events, then transcribes each completed speech segment with Faster-Whisper. This is not token-by-token model-native Faster-Whisper decoding, so partial transcript deltas may not be available.

## Compare other models after the baseline

The services are independent. Keep the same input, room, and device settings, change one backend at a time, and compare recognition accuracy, first-text latency, first-audio latency, playback gaps, and recovery after interruption.

- **Multilingual Whisper:** the Orin quick start's `tiny.en` is English-only. For a multilingual comparison, download `Systran/faster-whisper-small` into Speaches, reload the ASR model list, and select the matching input language. Larger variants such as `large-v3-turbo` are comparison candidates, not guaranteed latency improvements.
- **Gemma:** keep E2B as the small text baseline, or compare [Gemma 4 12B](/models/gemma4-12b/) with its matching multimodal projector for image understanding. The E2B quick start deliberately disables the projector; enabling vision requires a vision-capable serving configuration as well as the workbench setting.
- **Qwen3-TTS:** [1.7B CustomVoice](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice) can be served through an OpenAI-compatible speech endpoint, for example with [vLLM-Omni](https://docs.vllm.ai/projects/vllm-omni/en/latest/). Select **OpenAI REST API**, the model endpoint, and a supported voice such as `ryan`. Start without early TTS, then compare overlap.

<Note title="Qwen3-TTS streaming and future voice controls">
  In the evaluated vLLM-Omni setup, an explicit provider streaming request returned PCM before synthesis finished. VAW 0.2.0's generic REST adapter does not send that provider-specific `stream` field, and the same server buffered that request. Do not attribute native streaming timing to the released application. Dedicated instructions, VoiceDesign, and reference-voice cloning controls remain separate 0.3.0 development work.
</Note>

For model installation and lifecycle details, see the [Speaches guide](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/v0.2.0/docs/setup_speaches_jetson.md) and [NVIDIA open speech guide](https://github.com/NVIDIA-AI-IOT/multi_modal_ai_studio/blob/v0.2.0/docs/setup_open_models_jetson.md).

## Troubleshooting

<details>
<summary>Speaches reports <code>No models found</code></summary>

Confirm the service and installed models, then rerun the idempotent start command if either starter model is missing:

```bash
cd ~/voice-workbench-backends
./scripts/speaches_speech.sh status
./scripts/speaches_speech.sh models
./scripts/speaches_speech.sh start
```

</details>

<details>
<summary>Gemma or Kokoro fails to load on an 8 GB Orin Nano</summary>

Stop unrelated GPU containers, keep the default tiny ASR model and 2048-token Gemma context, and confirm that swap is active:

```bash
docker ps
free -h
swapon --show
```

The recommended configuration was qualified with a 16 GB swap file. Swap helps with transient CPU allocations during loading, but it does not increase GPU memory. If memory pressure continues, use a smaller OpenAI-compatible LLM while keeping the same speech service.

</details>

<details>
<summary><code>voice-ai-workbench: command not found</code></summary>

Activate the Python virtual environment before launching:

```bash
source ~/voice-workbench-venv/bin/activate
voice-ai-workbench --help
```

</details>

<details>
<summary>Port <code>8092</code> is already in use</summary>

Identify the listener before stopping anything:

```bash
ss -ltnp 'sport = :8092'
```

If it is your existing workbench process, stop it with **Ctrl+C** in its terminal. Otherwise, leave that service running and choose another port, for example `voice-ai-workbench --preset speaches-jetson --port 8101`, from outside the backend checkout.

</details>

<details>
<summary>vLLM fails to start because ports are busy</summary>

Use an unused port, such as `--port 18087` in the Thor example, and match it in the workbench's LLM API base URL. Check `docker ps` and `ss -ltnp` before stopping an existing service.

</details>

<details>
<summary>Browser cannot access the microphone or camera</summary>

Make sure you opened the HTTPS URL:

```text
https://<JETSON_IP>:8092
```

Verify the Jetson address before accepting its self-signed development certificate, then allow browser permissions for microphone and camera.

</details>

<details>
<summary>ASR does not resume after being muted for a long time</summary>

The ASR stream can time out if it stops receiving audio for an extended period. Stop the session with the red button, then start a fresh session.

</details>

<details>
<summary>GPU memory is not released after stopping vLLM</summary>

Check whether another model process or container is still running:

```bash
docker ps
free -h
```

Stop only the model services you no longer need. Linux page-cache reclamation does not release memory held by a live inference process; do not use `vm.drop_caches` as a GPU-memory fix.

</details>

## Next Steps

- Change the system prompt to create a different assistant personality.
- Enable barge-in and test interrupting the assistant while it is speaking.
- Compare REST ASR with the Realtime transcription preset after checking the backend limitation above.
- Try Nemotron 3.5 ASR and Magpie TTS through the NVIDIA open model services.
- Try another OpenAI-compatible TTS backend, voice, language, or speaking speed.
- Try a USB camera connected directly to Jetson.
- Compare latency with vision enabled and disabled.
- Save your favorite configuration as a preset.
- Compare Cosmos3-Edge with another independently served LLM/VLM while keeping the speech models fixed.
